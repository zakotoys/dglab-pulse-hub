# dglab-pulse-hub 实施计划

## 文档目的

本目录把 [PRD](../prd.md) 与 [TRD](../trd.md) 转换为可以逐步交付、逐项验收的实施计划。计划遵循三个原则：

1. 每个阶段结束时都保留一个可以运行和验证的产品，不并行铺开未闭环的客户端。
2. 格式事实、样例观察和社区推断分级管理；未经证实的推断不能成为静默转换规则。
3. 按测试驱动开发推进。每个行为先有失败测试或验收夹具，再实现最小代码，最后重构。

## 状态定义

计划项只使用以下状态，避免用百分比掩盖未闭环工作：

- `Not started`：尚未开始。
- `In progress`：已有失败测试、实验分支或实现工作，但尚未满足退出标准。
- `Blocked`：缺少明确列出的外部证据或决策，继续实现会制造错误语义。
- `Done`：实现、自动化测试、文档与可复核产物全部满足该项退出标准。

当前仓库只有定义文档和 `.example` 语料，所有实施阶段均为 `Not started`。文档编写完成不等于对应功能完成。

## 计划变更规则

- 改变用户范围、发布边界或数据保留政策时，先新增或替代 PDR。
- 改变包边界、依赖方向、领域模型或跨进程契约时，先新增或替代 ADR。
- 新证据推翻格式假设时，直接更新目标规则和夹具；不为尚未发布的错误规则保留兼容层。
- 每个合并请求只推进一个可说明的行为切片，并同步更新 [需求追踪矩阵](traceability.md)。
- 阶段不能仅凭“代码已写完”结束，必须保存测试报告、样例清单或发布产物等完成证据。

## 文档权威顺序

发生冲突时按以下顺序处理：

1. 已接受的 PDR/ADR 决策记录。
2. PRD/TRD 中带 ID 的当前需求与技术约束。
3. 本目录中的实施顺序和验收门禁。
4. research 文档中的外部事实与推断。
5. README 中的概览性说明。

格式事实本身另按 [格式基线计划](format-baseline.md) 的证据等级判断。计划不能把低等级来源提升为官方规范。
