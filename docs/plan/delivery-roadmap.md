# 交付路线图

## 1. 路线图目标

路线图从最小的可验证内核开始，逐层加入传输适配器和交互界面。每个里程碑都必须能独立运行、能由固定夹具复现，并且后续阶段只能建立在前一阶段已经通过的公开契约上。

```text
M0 格式证据与工程骨架
  -> M1 .pulse 核心 + CLI 闭环
  -> M2 Web/Electron 单文件工作台
  -> M3 批处理、QR 与图像导出
  -> M4 可撤销编辑与经验证的规则变换
  -> M5 生产部署与发布加固
```

设备通信不在这条主路径内。只有新的 PDR 明确改变产品边界后，才能规划设备 adapter。

## 2. 里程碑总览

| 里程碑 | 产品结果 | 关键需求 | 前置条件 | 状态 |
| --- | --- | --- | --- | --- |
| M0 | 格式事实可测试，仓库可持续开发 | VAL-001～004 的证据基础 | 无 | Not started |
| M1 | CLI 完成“导入 -> 校验 -> metadata/stream -> 导出 -> 再导入” | IO-001、IO-003、VAL-001～004、PRE-001/002/006、EDIT-006、TASK-001 | M0 | Not started |
| M2 | Web 与 Electron 都能完成单文件工作流并给出一致结果 | M1 全部、跨端一致性、基础 hover | M1 | Not started |
| M3 | 批量、QR 和 SVG/PNG/JPG 形成完整的 P1 IO 能力 | IO-002/004/005/006、TASK-002/003 | M2；QR 证据门禁 | Not started |
| M4 | 可撤销编辑、差异比较和有证据的格式规则变换 | EDIT-001～005、VAL-005/006 | M3；规则夹具门禁 | Not started |
| M5 | Docker Compose 与桌面安装包可重复发布 | 部署、安全、性能、可观察性要求 | M2；需要发布的 P1 能力已完成 | Not started |

M5 的部署工程可在 M3/M4 期间准备，但不能绕过 M2 的跨端一致性门禁提前宣称可发布。

## 3. M0：格式证据与工程骨架

### 3.1 可交付结果

- `.example` 中 16 个文件成为只读的来源语料，生成可审阅的清单与特征统计。
- 每条格式规则都有证据等级和规则 ID；未知字段保持原始索引语义。
- 建立 npm workspaces、TypeScript strict、单元测试、覆盖率、lint/format 和 CI 的最小骨架。
- `pulse-core` 可以识别输入类型并对一个最小合法字符串建立语法树，但不提前实现完整产品。

### 3.2 顺序

1. 冻结语料哈希和统计；为每个文件记录来源是否可确认。
2. 从样例提取合法字符、分隔符、字段数、数值形式和观察范围。
3. 为最小合法输入、每一种分隔符错误和数值词法错误先写失败测试。
4. 建立只表达索引和原始小数的语法模型，再实现最小解析器。
5. 运行官方 App 的导入/导出实验；无法运行时，把相关语义保留为待验证，不用社区结论替代官方事实。

### 3.3 退出门禁

- 16 个样例全部能被词法/结构解析，且没有静默丢字段。
- 非法夹具至少覆盖前缀、等号、section 分隔符、头字段数、点字段数、空字段、非有限数和尾随内容。
- 解析器对任何错误都返回稳定 code 与位置，不向调用方抛出未经分类的异常。
- 格式规则表明确标注哪些值只是语料观察范围，哪些是产品支持上限。
- CI 在受支持 Node.js LTS 上从干净检出执行成功。

详细任务见 [格式基线计划](format-baseline.md)。

## 4. M1：核心与 CLI 纵向闭环

### 4.1 用户可见结果

用户可以在命令行对单个 `.pulse` 执行：

```text
inspect <input.pulse>
  -> 类型识别
  -> 解析和校验
  -> 分层 metadata 与诊断
  -> index-based WaveformStream 摘要

export <input.pulse> <output.pulse>
  -> 导出前校验
  -> 规范序列化
  -> 再导入语义等价检查
```

CLI 是长期保留的自动化入口，不是一次性脚手架。Electron 与 API 后续调用同一应用用例，不复制 CLI 逻辑。

### 4.2 实现切片

1. **识别切片**：字节读取、UTF-8 校验、BOM/换行政策、输入类型诊断。
2. **结构切片**：全局设置、section 头、强度点、来源位置、原始 token。
3. **校验切片**：结构、观察范围、支持范围和语义规则分层执行。
4. **派生切片**：以 `100 ms` 点粒度展开启用 section；无法确认的频率/时长索引仍以索引展示。
5. **序列化切片**：只输出一个规范格式；导出后强制再解析并检查语义等价。
6. **用例切片**：统一 `Result`、诊断、metadata、规则集 ID 和任务状态。
7. **CLI 切片**：稳定退出码、JSON 输出和面向人的摘要输出。

### 4.3 退出门禁

- 所有 `.example` 文件通过导入、规范导出、再导入语义等价测试。
- 原始索引、小数数值、锚点状态、section 顺序和启用状态在往返中不丢失。
- 一个非法文件不会产生输出文件；命令退出码和诊断可由脚本判断。
- `pulse-core` 不依赖 Node.js 文件系统、HTTP、Electron 或 DOM。
- CLI 测试从真实文件边界执行，而不是只直接调用解析函数。

详细任务见 [核心闭环计划](core-mvp.md)。

## 5. M2：Web/Electron 单文件工作台

### 5.1 交付顺序

1. 先建立共享的 transport-neutral 用例 DTO 和契约测试。
2. Web API 只实现单请求、内存处理的 inspect/export，不持久化用户文件。
3. Web 工作台完成导入、诊断、metadata、时间轴和导出。
4. Electron 主进程通过 IPC 适配相同用例；renderer 复用工作台视图与 view model。
5. 对同一夹具运行 CLI/API/IPC 契约一致性测试。

### 5.2 退出门禁

- Web 与 Electron 首屏直接进入可用工作区。
- 同一输入在 CLI、HTTP 和 IPC 中得到相同规则集 ID、诊断 code、metadata 和 stream 数据。
- renderer 无 Node.js 文件权限；Electron 使用 context isolation、sandbox 和窄 preload API。
- Web 上传在请求结束后释放，日志不记录完整内容或原始文件名。
- 时间轴在最长语料和设计上限夹具下仍可缩放、悬停且不阻塞主线程。

## 6. M3：批处理、QR 与图像导出

M3 由三个独立纵向切片组成，按以下顺序完成，每个切片单独满足测试门禁后再开始下一个：

1. **批处理**：单文件用例组合、并发上限、取消、冲突命名、逐文件结果。
2. **矢量导出**：先实现共享绘图场景到 SVG，再通过选定的成熟库栅格化 PNG/JPG。
3. **QR adapter**：只有获得当前目标 App 的真实 QR 夹具并关闭 OQ-003 后才开始；不得假设它只是 `.pulse` 文本的透明压缩。

M3 退出时，部分失败的批量任务必须保留其他成功结果；三种图片格式使用同一 stream 快照；QR 必须完成“App 导出 -> 本项目导入”和“本项目导出 -> App 导入”实测。

## 7. M4：编辑与规则变换

### 7.1 编辑顺序

1. 领域命令与不可变文档快照。
2. 单点强度/锚点编辑。
3. section 频率索引、模式和持续时间索引编辑。
4. 修改前后结构/stream diff。
5. 撤销/重做命令栈。
6. 只重算受影响自动点的插值。

### 7.2 规则变换门禁

“旧版本升级”不是默认兼容层。开始实现前必须同时具备：

- 可区分的源方言和目标方言；
- 至少一组真实源/目标夹具；
- 逐字段转换表和不可表达项政策；
- App 或权威实现的往返验证；
- 新 PDR 明确其产品价值和支持期限。

未满足门禁时，VAL-005 保持 `Blocked`，产品只报告不支持的方言。

## 8. M5：生产发布

### 8.1 Web 交付

- Web 静态资源、Node.js API、Nginx 的 Docker Compose 组合。
- 非 root 容器、只读根文件系统（适用时）、临时目录配额、健康检查、优雅停止。
- Nginx 只做静态资源、TLS 边界和反向代理；不解析 Pulse。
- 压力测试给出文件大小、点数、并发和超时的最终生产上限。

### 8.2 Electron 交付

- 使用 Electron 官方推荐的 Forge 路径制作安装包。
- Windows 首发安装包及校验和；其他平台只有 CI 实机验证后才列为支持。
- CSP、context isolation、sandbox、导航/新窗口拦截和文件访问边界均有自动化或审计证据。

### 8.3 发布退出门禁

- 从干净环境可重复构建容器和桌面产物。
- SBOM、依赖许可证与高危漏洞检查完成。
- 发布说明列出规则集 ID、已知限制和不支持格式。
- 回归套件、跨端一致性、资源上限和备份/恢复（如未来引入持久化）全部通过。

## 9. 明确不做的并行工作

- M1 未结束前不搭建完整编辑器。
- M2 未结束前不加入账户、数据库、公开分享或多租户。
- 没有真实 QR 夹具前不实现二维码编码器。
- 没有目标格式证据前不实现“旧版本升级”。
- 没有新 PDR 前不实现设备发现、配对、真实播放或强度控制。
