# `.example` 本地 `.pulse` 语料分析

## 1. 目的与证据等级

本文记录 2026-08-30 对工作区 `.example/*.pulse`
的只读统计，用于约束首版 parser、validator 和测试计划。它证明“样例中实际出现了什么”，不证明完整合法范围、文件来源、官方版本或 DG-LAB
App 必然接受所有样例。

证据优先级：

1. 官方帮助/协议可确认产品语义和设备协议边界。
2. 本地语料可确认待支持输入的具体语法事实。
3. 社区实现可提供字段映射候选，但必须经过本项目测试和 App 互操作验证。

`.example/` 当前被 `.gitignore`
排除。样例可用于本地研究，但在确认来源、许可证和可再分发性前，不应直接复制进发布包或公共测试夹具。CI 使用从规则派生的最小合成夹具；获得授权后再登记原样 corpus
manifest。

## 4. 字段观察

### Global

| 位置 | 观察值         |
| ---: | -------------- |
|    0 | `0, 8, 18, 35` |
|    1 | `1, 2, 4`      |
|    2 | `0, 1, 8, 16`  |

这些值支持“三个全局字段”的语法事实，不足以独立证明字段名称、单位和完整范围。第三字段尤其不应在未验证时强制命名为频率平衡。

### Section header

|              位置 | 观察范围/值       |
| ----------------: | ----------------- |
| 0：频率索引候选 A | `0..83`（非连续） |
| 1：频率索引候选 B | `0..69`（非连续） |
|   2：时长索引候选 | `0..73`（非连续） |
|       3：频率模式 | `1, 2, 3`         |
|       4：启用状态 | `0, 1`            |

样例没有出现模式 4，但官方帮助明确存在模式 4。因此测试必须包含合成模式 4 夹具，不能把 corpus 覆盖误当作合法值全集。

### 曲线点

- 形态为 `<decimal>-<0|1>`，逗号分隔。
- 强度存在 `15.00`、`39.80`、`1.45` 等小数，不能在 parser 中先 `Math.round`。
- 自动点与锚点均大量存在；有些 section 全部是锚点。
- 最短 section 恰有两个点，最长有 106 个点。

## 5. 与官方说明的关系

官方帮助页确认：

- 每个小节由一个脉冲元完整重复组成。
- 每个竖条/曲线点对应 0.1 秒。
- section 目标时长不能截断脉冲元，重复次数向上取整。
- 频率模式有 1..4 四种作用域。

官方帮助页同时描述 UI 中最多三个连续小节，而本地语料包含最多十个且可全部启用。首版文件 parser 因此支持 corpus 中的 1..10 个 section，并把“官方 UI 最多三个”记录为互操作待验证差异，不据此拒绝第 4..10 个 section。

## 6. 测试使用规则

- 为每个观察到的结构特征建立最小合成夹具；不要让测试只能靠大型真实文件定位失败。
- 本地可选 corpus suite 扫描 `.example`，缺少目录时明确 skip，不把缺失当成功覆盖。
- corpus 测试断言完整消费、section/点位统计和语义往返，不断言未确认的物理 Hz。
- 任何改变 corpus 统计或诊断的实现都必须先说明是规则修正还是回归。
- 真正的兼容矩阵必须记录 DG-LAB App 版本、平台、文件哈希和实际导入结果。

## 7. 仍需验证

- 三个 global 字段的精确名称、单位和范围。
- 两个频率索引与物理频率/周期的完整映射。
- 时长索引的完整映射及速度字段对逻辑时间的影响。
- 自动点在 App 内的精确插值函数和小数舍入方式。
- 4.x App 对 4..10 个启用 section 的导入与播放行为。
- canonical serializer 的小数位数、空白和末尾换行容忍度。
- QR envelope 在当前 App 的实际互操作结果。

这些问题分别进入
[交付计划的依赖门槛](../plan/README.md#5-依赖与决策门槛)，不得在实现中使用无诊断默认值绕过。
