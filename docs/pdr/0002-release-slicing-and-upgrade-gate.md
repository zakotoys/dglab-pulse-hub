# PDR-0002：分层发布与版本升级证据门槛

| 项目 | 内容                              |
| ---- | --------------------------------- |
| 状态 | Accepted                          |
| 日期 | 2026-08-30                        |
| 关联 | 全部 P0/P1，重点 VAL-005、VAL-006 |

## 背景

PRD 同时描述核心、Web、Electron、批量、编辑、图片、QR 和旧版本升级。若并行铺开所有外壳，项目会在领域规则尚未验证时积累多套未完成实现。尤其“旧版本升级”目前没有可识别版本字段、旧/新夹具对或官方转换规则，无法做成可信功能。

## 决策

采用 [交付总计划](../plan/README.md) 的 M0-M5 顺序：

1. M0 用语料和测试固定格式证据。
2. M1 用 Node 命令交付单文件核心闭环。
3. M2 在同一用例上交付 Web 工作台。
4. M3 复用工作区交付 Electron 离线应用。
5. M4 逐项加入 QR、批量、图片、播放模拟和编辑。
6. M5 完成生产部署与发布门禁。

每个里程碑独立可运行；后续里程碑不得以破坏前一闭环为代价。

### 升级门槛

VAL-005/VAL-006 是条件能力。只有同时具备以下材料才可进入开发：

- 能确定识别旧画像和目标画像的方法。
- 至少一份真实旧输入与对应目标输出，来源和哈希可追踪。
- 字段级、点位级变更规则，明确二次函数适用的区间、端点、舍入和裁剪。
- 变更记录的用户可理解呈现。
- 目标 DG-LAB App 的导入/导出互操作结果。

门槛未满足时，首个完整版本可以不包含升级；产品不得提供“自动尝试”“兼容模式”或静默补点。

## 不采用的方案

- **先搭完整 monorepo 和所有应用空壳**：无法验证用户价值，会造成大面积占位结构。
- **Electron 与 Web 同时起步**：过早增加两个运行边界，延迟核心规则反馈。
- **根据社区解析器猜测升级规则**：缺少输入版本识别与官方互操作证据。
- **为将来设备播放预留当前实现**：设备 adapter 是独立 P2 立项，不影响文件闭环。

## 影响

- PRD 中 P1 升级不再是首个完整版本的无条件发布门槛。
- 各里程碑通过追踪矩阵和质量门禁验收，不以日期或代码量验收。
- M1 的 Node 命令是首个可运行产品入口，不被视为一次性脚手架。
- 如果升级证据后来成立，直接实现当时确认的目标画像，不保留早期猜测路径。
