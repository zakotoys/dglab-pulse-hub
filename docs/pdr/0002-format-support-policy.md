# PDR-0002：`.pulse` 格式支持与证据政策

## 状态

Accepted — 2026-08-30

## 背景

DG-LAB 官方资料公开了自定义波形的 UI 语义和设备协议，但没有发布 `.pulse` 明文的完整字段规范。仓库 16 个样例使用：

```text
Dungeonlab+pulse:<3 globals>=<5-field section>/<strength>-<anchor>[,...]
```

第三方对官方分享二维码的实测则解出另一种 legacy payload：固定元数据字段与 `<type>-<strength>` 点，强度范围和 section 表达也不同。当前 `.pulse` 文本没有可见版本标记，不能可靠地从内容声称其具体 App 版本。

## 决策

### 1. 首个规则集只支持 current numeric-triple `.pulse`

支持配置以 `.example` 语法和经验证的目标 App 实验为基础。顶层非三个数字的同前缀社区方言明确拒绝，不自动套用其他解释。

初始文档类型报告为 `dglab-pulse-text`，并携带 `ruleSetId`；不虚构 `formatVersion`。只有来源 metadata 明确提供 App 版本时才展示来源版本，而且它不参与解析成功判定。

### 2. 索引语义是权威值

全局、频率和时长字段先作为原始索引保存。Hz、秒、频率压缩值等均为命名规则集的派生结果，必须携带来源/置信度，不能覆盖源索引。

如果物理映射未通过目标 App 验证，MVP 使用 index-based preview，而不是给出看似精确的错误单位。

### 3. 规范输出，不保留任意原格式

导入保存原始文本快照用于诊断和 diff；导出只产生一个规范表示，并保证受支持语义往返等价。未知字段、额外尾随数据和无法确认的方言不进入可编辑 `PulseDocument`，因此 serializer 不需要“原样透传”路径。

规范小数和换行政策必须由 OQ-006 关闭后定稿。

### 4. UI 上限与解析上限分离

当前官方帮助描述最多三个连续 section，但语料包含最多十个。初始支持配置可解析 1–10 个 section；超过三个时给出 App 互操作 warning。十个是当前产品支持上限，不宣称为官方协议上限。超过上限直接拒绝，不做截断。

其他资源上限在 M0 基准后以规则常量定稿；不先提供用户可调的无限配置。

### 5. QR 使用独立 adapter 和模型

QR 只在有目标 App 夹具、逐字段转换表和双向互操作证据后支持。它不能与 `.pulse` parser 共用“解压后必定得到 `.pulse` 明文”的假设。

在门禁关闭前，系统最多识别 `qr-share-candidate` 并报告不支持，不生成 QR。

### 6. 不实现未定义的旧版本兼容

没有可识别源方言、目标方言和真实转换夹具时，不提供“旧版本升级”。未知输入明确拒绝。未来若增加升级，它是显式产品用例，不是导入 fallback，并需要新 PDR。

## 诊断政策

- `error`：语法/范围/资源越界、未知方言、会丢失语义的情况。
- `warning`：语法受支持但目标 App 互操作未验证，例如 section 数大于当前官方 UI 能创建的数量。
- `info`：规范化词法差异、派生规则集说明。
- 不提供默认静默修正；任何显式修正都产生 change set。

## 未选择的方案

### 按前缀宽松解析所有方言

拒绝。相同前缀下字段语义可能不同，宽松解析会产生不可见的数据错误。

### 把 QR 当作压缩 `.pulse`

拒绝。现有第三方实测与 current 样例结构冲突。

### 完全保留源文本格式

拒绝。为任意词法细节建立 round-trip AST 增加复杂度，而当前产品只需语义等价和可见 diff。必要原始 token 可用于定位，但不是第二套 serializer。

## 影响

- PRD/TRD 中“版本识别”解释为方言/ruleset 识别，不从无版本字段的文本猜 App 版本。
- VAL-005、IO-002、IO-004 在证据门禁关闭前保持 Blocked。
- 格式研究必须清楚区分官方事实、语料观察和社区逆向。
- 规则变化直接替换尚未发布的错误路径，不增加兼容 fallback。
