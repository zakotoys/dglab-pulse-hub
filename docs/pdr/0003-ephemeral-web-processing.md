# PDR-0003：Web 端无持久化处理

## 状态

Accepted — 2026-08-30

## 背景

PRD 将 Web 文件保存、账户、配额、多租户和公开分享列为待决策。实现这些能力会引入身份、数据库/对象存储、删除与保留政策、滥用处理和运维责任，但它们不是 `.pulse` 单文件工作流的必要条件。

## 决策

M2/M3 Web 服务采用无账户、无用户文件持久化的单请求处理模式：

- inspect/export 请求在受限内存或受控临时目录处理；响应结束、取消或超时后清理。
- 不生成可稍后访问的文件 ID、任务分享链接或公开 URL。
- 不建立用户数据库、对象存储、最近文件列表或服务端编辑历史。
- 日志只记录 request ID、操作、大小桶、耗时、结果状态和诊断 code；默认不记录完整文件名、内容或规范 Pulse DTO。
- M2 只处理单文件同步请求。批量可以在 M3 作为一次请求内的有界任务处理，不演变为持久化后台队列。

Electron 的最近文件和本地历史若以后需要，只能保存在用户本机，并由单独产品需求定义；本 PDR 不授权实现。

## 部署边界

无持久化不等于可以无保护地公开部署。公开互联网部署前仍必须明确：

- 入口鉴权或网络访问边界；
- 速率、并发、请求体和 CPU/内存限制；
- TLS、代理超时、滥用监控和隐私声明；
- 运营方日志保留与事件响应。

这些项目由 OQ-008 和 M5 发布门禁管理。

## 未选择的方案

### 匿名上传后返回分享链接

拒绝。它立即引入内容托管、枚举、删除、滥用和成本问题。

### 首发账户与云端任务库

拒绝。它不提升核心格式正确性，会扩大 M2 的不可验证范围。

### 服务端长期后台任务

拒绝。当前文件规模不证明需要队列和持久化任务状态；先用有界同步处理和取消。

## 影响

- API 契约不包含 file ID、user ID 或长期 task URL。
- Docker Compose 不需要数据库或对象存储服务。
- Web 和 Electron 的领域结果仍保持一致，但文件生命周期由各自 adapter 管理。
- 如果未来需要保存/分享，新增 PDR 替代本记录，并在实现前完成威胁模型和删除/保留政策；不在当前 API 中预埋兼容字段。
