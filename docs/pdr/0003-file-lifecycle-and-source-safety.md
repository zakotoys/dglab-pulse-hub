# PDR-0003：文件生命周期与源文件保护

| 项目 | 内容 |
| --- | --- |
| 状态 | Accepted |
| 日期 | 2026-08-30 |
| 关联 | IO-001..006、TASK-001..003、PRD 安全与隐私要求 |

## 背景

PRD 尚未决定 Web 文件是否持久化，也要求原始输入不被隐式覆盖。账户、分享、数据库和对象存储会显著扩大隐私、安全与运维范围，不是单文件工作台成立的必要条件。

## 决策

### Electron / Node

- 导入只读源文件并建立内存中的 source snapshot。
- 默认导出为“另存为”，不覆盖原路径。
- 用户明确选择原路径且通过最终确认时可以原子替换；先写同目录临时文件、校验成功后再替换。
- 失败或取消不留下看似成功的目标文件。
- 最近文件列表（若实现）只保存用户明确可见的路径引用，不保存波形内容。

### Web

- M2-M5 默认无账户、无长期保存、无公开分享。
- 优先内存处理；必须落盘时使用请求/任务专属临时目录。
- 成功、失败、取消和进程优雅停止都触发删除；下载完成不延长默认生命周期。
- API 返回任务结果和下载流，不返回服务器本地路径。
- 日志不记录完整内容、原始文件名或可反推内容的未加盐哈希。

### 扩展门槛

任何长期保存、账户、跨用户分享或对象存储都必须先有新的 PDR，明确所有权、鉴权、保留时长、删除、配额、备份、滥用处理和隐私告知。

## 不采用的方案

- **默认覆盖源文件**：与可恢复编辑和明确用户意图冲突。
- **先建立数据库以便未来任务管理**：当前单文件和短期批量任务无需持久化。
- **处理失败后保留临时文件用于调试**：会泄露内容；调试信息应使用脱敏诊断。
- **依赖 Nginx 定时清理**：应用必须拥有自己创建的临时资源生命周期。

## 影响

- M2 不需要数据库或对象存储，部署只包含 Web、API 和 Nginx。
- application result 使用逻辑 input/output descriptor，路径只存在于本地 adapter。
- E2E 和故障测试必须覆盖成功、失败、取消、断连和进程停止的清理行为。
- 若未来引入持久化，不保留临时模式的数据迁移兼容层；通过独立产品边界和明确 API 交付。
