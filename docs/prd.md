## 1. 产品概述

`dglab-pulse-hub` 是一个专门处理 DG-LAB 4 App `.pulse` 文件的波形工作台。用户可以导入
`.pulse`，检查文件与波形合法性，查看多层 metadata 和展开后的
`WaveformStream`，进行受控修改，最后导出新的 `.pulse`、二维码或预览图。

产品的核心价值是把“能否导入、波形实际表现如何、修改会产生什么结果、导出是否仍然有效”放在同一条可验证的工作流中。产品不以重新实现 DG-LAB
App、提供通用音频编辑器或承载设备通信为目标。

## 2. 目标与非目标

### 2.1 产品目标

- 让用户可靠地处理 DG-LAB 4 App `.pulse` 文件。
- 让用户在导出前看懂文件、section、脉冲元和曲线点的关系。
- 让校验、升级、插值和修改结果可解释、可追踪、可复核。
- 让 Electron 与 Web 端共享同一套产品行为和波形结果。
- 为单文件和批量任务提供一致的诊断和结果汇总。

### 2.2 非目标

- 不把 dglab-kit 的 JSON/JSON5/`.pulses` 数据包作为用户波形格式。
- 不实现 BLE、V3/V4 Socket 或其他设备传输协议作为当前核心能力。
- 不将未知社区方言静默转换为目标 `.pulse` 语义。
- 不把“文件合法”解释为“对人体安全”或提供医疗/安全保证。
- 不把设备实时输出、远程控制或服务端设备代理作为 MVP 必需能力。

## 3. 用户与使用场景

### 3.1 目标用户

| 用户          | 主要任务                            | 关键诉求                                     |
| ------------- | ----------------------------------- | -------------------------------------------- |
| 普通用户      | 导入、查看、轻量修改和分享 `.pulse` | 易懂、可视化、不会误导、导出可用             |
| 波形创作者    | 精细调整 section、脉冲元和强度曲线  | 点位级控制、修改可追踪、结果可复核           |
| 批处理用户    | 检查、升级、转换大量 `.pulse`       | 稳定、可重复、逐文件诊断、失败不影响其他文件 |
| 开发者/部署者 | 部署 Web 服务或集成处理能力         | API 与 Electron 行为一致、部署清晰、资源可控 |

### 3.2 主要场景

1. **导入并确认**：用户选择一个 `.pulse`
   或一批文件，系统识别格式/版本并输出文件级、Pulse 级和 section 级诊断。
2. **预览并理解**：用户查看 metadata、时间轴和强度可视化，悬停点位时获得来源和展开后的数值。
3. **修改并复核**：用户调整频率、持续时间、强度或曲线，系统显示修改前后差异，并在导出前重新校验。
4. **升级旧文件**：用户显式选择版本升级，系统按规则补点和记录变更，不对旧文件进行隐式覆盖。
5. **批量处理**：用户提交批量检查、升级或导出任务，获得逐文件结果和整体汇总。
6. **跨端使用**：同一份 `.pulse` 在 Electron 和 Web 中得到一致的诊断、stream 和导出结果。

## 4. 产品边界与核心概念

- `Pulse`：`.pulse` 文件解析后的脉冲波形文档，是产品的主要编辑对象。
- `WaveformStream`：从 Pulse 展开的有序波形序列，用于预览、播放模拟、编辑和预览图导出。
- `Metadata`：按文件、Pulse、section、stream 和点位等层级提供的描述信息。
- QR：`.pulse` 的分享封装，不是第二种波形语义，也不改变 Pulse 内容。

完整术语以 [Glossary](glossary.md) 为准。

## 5. 功能需求

需求优先级：`P0` 为最小可用闭环必需，`P1` 为首个完整版本重点，`P2`
为后续增强；优先级用于范围排序，不构成具体实现设计。

### 5.1 IO：导入与导出

| ID     | 优先级 | 需求                   | 验收要点                                                               |
| ------ | ------ | ---------------------- | ---------------------------------------------------------------------- |
| IO-001 | P0     | 导入 `.pulse` 明文文件 | 能读取合法文件；非法文件返回定位到阶段和字段的诊断；不静默接受未知语义 |
| IO-002 | P1     | 导入 QR 分享内容       | 能识别 `#DGLAB-PULSE#` 封装并还原为等价 Pulse；封装损坏时给出明确错误  |
| IO-003 | P0     | 导出 `.pulse`          | 合法 Pulse 可导出；导出结果可再次导入并通过校验；不丢失受支持的语义    |
| IO-004 | P1     | 导出 QR                | QR 内容还原后与导出前 Pulse 等价；失败时不生成误导性的分享内容         |
| IO-005 | P1     | 批量导入/导出          | 单文件失败不阻断其他文件；结果包含成功、失败、警告和诊断汇总           |
| IO-006 | P1     | 导出 stream 预览图     | 支持 SVG、PNG、JPG；同一 stream 的图形数据和视觉语义一致               |

### 5.2 检查与升级

| ID      | 优先级 | 需求               | 验收要点                                                                                   |
| ------- | ------ | ------------------ | ------------------------------------------------------------------------------------------ |
| VAL-001 | P0     | 格式和支持画像检查 | 能区分目标 `.pulse`、QR 封装和不支持输入；报告 profile、规则版本和判断依据，不伪造文件版本 |
| VAL-002 | P0     | 结构检查           | 检查顶层结构、全局设置、section 分隔、section 头和曲线点结构                               |
| VAL-003 | P0     | 范围检查           | 检查频率、时长、模式、启用状态、强度、锚点等字段范围                                       |
| VAL-004 | P0     | 语义检查           | 检查 section/脉冲元/曲线点组合是否能展开为有效 stream                                      |
| VAL-005 | P1     | 旧版本升级         | 升级是显式操作；原始输入不被隐式覆盖；结果包含变更记录和警告                               |
| VAL-006 | P1     | 二次函数插值       | 补点使用 `f(x) = 1 - (1 - x) ** 2`；起止点、锚点、归一化范围、取整和裁剪结果可验证         |

### 5.3 波形预览

| ID      | 优先级 | 需求                       | 验收要点                                                                   |
| ------- | ------ | -------------------------- | -------------------------------------------------------------------------- |
| PRE-001 | P0     | 文件与 Pulse metadata 预览 | 能区分文件级、Pulse 级信息，并显示诊断状态                                 |
| PRE-002 | P0     | stream 时间轴预览          | 能查看频率、时长、强度随时间的变化；长 stream 仍可操作                     |
| PRE-003 | P1     | stream 播放模拟            | 按 stream 时间顺序播放并提供播放、暂停、停止和进度状态；不表示真实设备输出 |
| PRE-004 | P1     | 强度可视化                 | 支持环形频谱与颜色强度映射；颜色不能替代数值和诊断                         |
| PRE-005 | P1     | 点位 hover metadata        | 显示时间、持续时间、频率、强度、section、脉冲元和来源/插值信息             |
| PRE-006 | P1     | stream metadata 预览       | 显示点数、总时长、频率/强度统计和展开警告                                  |

### 5.4 波形修改

| ID       | 优先级 | 需求               | 验收要点                                              |
| -------- | ------ | ------------------ | ----------------------------------------------------- |
| EDIT-001 | P1     | 编辑频率和持续时间 | 修改受字段范围约束；修改结果能够回到 Pulse 语义       |
| EDIT-002 | P1     | 编辑强度与曲线点   | 区分锚点和自动点；修改锚点后只重算受影响的自动点      |
| EDIT-003 | P1     | 智能化手动修改     | 提供基于起止点和约束的辅助修改，但用户始终能确认结果  |
| EDIT-004 | P1     | 修改前后对比       | 能查看结构、metadata 和 stream 变化，不只比较原始文本 |
| EDIT-005 | P1     | 撤销/重做          | 连续编辑可逆；撤销/重做不改变原始导入快照             |
| EDIT-006 | P0     | 导出前重新校验     | 任何修改、升级或格式化后都必须重新执行适用校验        |

### 5.5 任务与交付

| ID       | 优先级 | 需求           | 验收要点                                                   |
| -------- | ------ | -------------- | ---------------------------------------------------------- |
| TASK-001 | P0     | 单文件任务状态 | 至少包含待处理、处理中、成功、失败和取消状态               |
| TASK-002 | P1     | 批量任务进度   | 提供已完成数、失败数、警告数和可取消状态                   |
| TASK-003 | P1     | 结果可追踪     | 结果关联输入文件、操作、输出文件和诊断，不依赖 UI 临时状态 |

## 6. 体验要求

- 首屏应能开始导入或打开最近任务，不以营销内容替代工作区。
- 合法性、警告和错误必须以文字和可定位信息表达，不能只用颜色或图形暗示。
- 预览图和时间轴应支持从全局概览进入点位级细节。
- 修改操作必须有明确的当前状态、未保存状态和恢复路径。
- 批量任务必须允许查看单个文件详情，不只展示总数。
- 本地播放模拟和真实设备输出必须使用不同的产品名称与状态。

## 7. 安全、隐私与使用边界

- 文件合法性检查不等价于人体使用安全性；产品不得承诺医疗、安全或刺激效果。
- 真实设备输出属于后续独立能力，默认不应由导入或预览动作触发。
- Web 端上传内容的保存、删除、访问控制和日志策略必须在上线前明确；默认按最小保存原则处理。
- 批量任务必须限制文件大小、数量、处理时长和资源消耗，避免单个请求耗尽服务资源。
- 错误、日志和分析数据不应默认记录完整波形内容或可识别的用户文件名，除非用户明确同意。

## 8. 版本与发布范围

### MVP（P0）

完成 `.pulse` 单文件导入、严格校验、Pulse/stream 基础预览、导出 `.pulse`
和导出前重新校验，并让 Electron 与 Web API 共享结果语义。

### 首个完整版本（P1）

加入批处理、QR、SVG/PNG/JPG、点位 metadata、stream 播放模拟、修改对比和撤销/重做。显式旧版本升级只有在
[PDR-0002](pdr/0002-release-slicing-and-upgrade-gate.md)
的证据门槛满足后才纳入该版本，否则独立延期且不影响其他 P1 能力发布。

### 后续增强（P2）

加入复杂编辑辅助、Web 端账户与任务管理、可选设备播放 adapter，以及经过单独评审的其他格式支持。

## 9. 成功标准

首个完整版本应满足：

- 合法 `.pulse` 的导入、预览、修改和导出形成闭环。
- 非法输入能返回可定位、可理解的诊断，而不是崩溃或静默修正。
- 导出文件重新导入后，其受支持语义与导出前一致。
- Electron 和 Web API 对相同输入产生一致的校验、stream 和导出结果。
- 批量任务的单文件失败不会污染其他文件的结果。
- 已实现的版本升级和插值变更可以被用户和测试夹具复核；未满足证据门槛时产品不提供猜测性升级。
